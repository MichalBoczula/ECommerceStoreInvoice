## Probes and real outage boundaries

All three health routes return their exact framework text/status/media/cache
contract over five populated collections. Alias and liveness issue no readiness
commands. Healthy readiness executes actual hello and database ping. Exact startup
index keys and uniqueness are inspected without changing data.

One case owns a real Mongo replica container. It stops only that container after
the host is running: alias/liveness remain Healthy, readiness becomes Unhealthy
503 and both documentation routes remain byte-identical to complete source
projections. Restarting the same Mongo restores readiness and every original field
and ordered line. Shared test containers are never stopped. The owned restart fixture initializes
the replica only when needed, records owned/shared container identities and bounds
container operations; it does not repeat first-start initialization on restart. A separate owned
standalone Mongo permits startup indexes but its actual hello is not a replica
set/router; readiness is 503 and executes no ping. Normal reads remain possible.
The test-only readiness client records actual commands and uses bounded selection
and heartbeat settings. Production's client/settings and five-second registration
timeout are unchanged. These native containers do not establish deployed Azure
DocumentDB or ingress failure/recovery behavior.

## Cancellation and host isolation

Two cases hold one real immutable local PDF stream after opening before headers,
or after its first 32 bytes during body copying. Cancelling the actual HTTP request
propagates RequestAborted, closes the actual stream and records a transport/body
failure. No completed status or HTTP 499 is invented. The next actual download
matches the entire original PDF bytes/hash, filename and private/no-store headers.
Both physical artifacts and all five populated collections remain unchanged.
This covers local file cancellation; existing private Blob adapter checks remain
distinct. It does not claim client receipt of the partial server-read bytes.

Two actual hosts reuse the same business IDs with deliberately different values
in all five collections, but use distinct databases. Complete HTTP reads return
each host's own cart, latest client version, snapshot-backed orders and historical
invoice metadata. Disposing the peer actually drops only its database; the primary
host, database and readiness survive. Registered async cleanup closes additional
clients/hosts even after a failure and surfaces cleanup errors.

complete comparison. The validation table now explicitly records all eight policies,

claim that reading documentation executes policies or completes Task 14's semantic
flow/rule/RAG-link audit. Swagger JSON matches the complete generated document with

exporting all generated OpenAPI/flow/policy sources with unavailable Mongo.
Two Infrastructure cancellation cases separately verify hello/ping token handling.
